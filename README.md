# Support Studio / 技术产品支持助手

面向技术产品支持的本地原型：型号确认 → 手册检索 → 来源展示 → 工单草稿。

## 运行

Python 3.9+，无第三方依赖。在本目录运行：

```sh
python3 app.py
```

浏览器打开 http://127.0.0.1:8765 。在 VS Code 中打开本目录即可开发。停止服务使用 Ctrl+C。

## 当前边界

- NX-100/NX-200 和所有手册内容均为本项目自编的虚构演示数据，不能用于真实设备。
- 默认为**本地关键词检索演示**，展示匹配原文，不是大模型回答，也不代表完整回答。没有向量检索，不应称作成熟 RAG 或自主 Agent。
- 已实现型号过滤、缺型号/冲突追问、未命中转人工建议、中英原文、引用、可编辑工单与下载、会话内反馈。刷新后会话不保留。
- 工单只下载，不自动发送。不会读工作区简历或上传私人文件。
- 有真实模型适配器，未配置密钥时禁用。使用 OpenAI 兼容的 Chat Completions JSON 模式协议（默认地址为 DeepSeek，已在 Gemini 的兼容接口上实测）；设置 `SUPPORT_API_KEY`、`SUPPORT_MODEL`，可选 `SUPPORT_API_URL` 后重启。密钥只在服务端环境中使用，不返回浏览器。
- 选择真实模式会把当前问题和检索到的示例资料发送给配置的服务商。2026-11-11 已在 `gemini-3.5-flash-lite` 上跑完 48 题评测，结果和失败案例见 `eval/RESULTS.md`。
- 引用 ID 校验只保证来源属于本次检索，不保证内容逻辑蕴含。真实回答仍需人工核对；不具备生产使用保证。
- 服务只绑定本机回环地址。当前没有认证/限流/多用户隔离，不可直接改为公网部署。

## 架构与学习路线

`web/index.html`：界面与交互。`app.py`：接口、基线检索、型号规则、可选模型调用。
`data/manuals.json`：带稳定来源ID的双语资料。`tests/test_app.py`：关键行为检查。

先读 `answer()` 理解请求如何分流，再读 `retrieve()` 理解为什么关键词检索会漏答。
下一轮优先找真实的、获准使用的文档和用户问题来改进检索（评测显示关键词检索漏答 4/48），而不是堆叠框架。

## 真实模型评测

```sh
source <你的环境变量文件> && python3 eval/run_eval.py   # 可加 --only 01,05
```

题集在 `eval/cases.csv`（48 题：正常、型号路由、资料不足、口语漏答、诱导编造）；脚本先自动初判，结果写到 `eval/results/`，再人工复核。2026-11-11 的结论（`gemini-3.5-flash-lite`，单次运行）：

- 编造事实或伪造引用 0 次；型号路由 9/9 正确。
- 第一次运行发现 6 题协议问题：状态与引用矛盾 3、空回答通过校验 2、`answer` 为 null 1。修复校验和提示词后全量回归，降为 0。
- 遗留：关键词检索漏答 4 题，没有处理。

样本小、只跑一次，结论只说明问题类别，不代表比率。
